# v0.3.1 陪伴口吻与「聊聊」修复

## 元信息

- **版本**：v0.3.1（v0.3.0 的补丁版）
- **发布**：2026-10-20
- **主题**：修复实机反馈的两个问题——难过时仍在吐槽、「聊聊」转移后模型不知道留言内容
- **对应代码**：`src/down_note/agent/prompts/companion.py`、`src/down_note/api/entries.py`、`frontend/src/components/chat/ChatPanel.vue`
- **数据变更**：无（无表结构变更、无迁移）

## 背景

v0.3.0 发布后的实机对话暴露两个问题：

1. **情绪回应只有一种姿态**：默认人格里「先接情绪、先一起吐槽」是全局规则，场景示例也全是骂事/骂人。模型忠实执行——用户明显低落时仍在吐槽。吐槽解决的是「不满」，不是「难过」，用户体感是「很冷、没被安慰」。
2. **「聊聊」转移没有进入模型上下文**：转移只写了 `messages` 表并推 SSE，没写进 LangGraph checkpointer 的图状态。界面看得见留言、主图上下文里没有，用户追问「你摸到什么」时模型一脸茫然。

另有一个连带问题：首次分型修订后，模型退化成「复述情绪 + 每句反问」的咨询师腔，用户两次问「该怎么办」只得到「先别想」和无关反问，体感更冷。第二层规则在同一版本内补齐。

## 方案要点

### 1. 默认人格改为情绪分型

默认人格（`DEFAULT_PERSONA` 的风格层）最前面加判断，每条消息重新判断、不沿用上一条：

- **气**（怪别人、被冒犯、受了气、倒霉）：站队吐槽，骂事情或对方，不骂用户。
- **难过**（怪自己、委屈、失落、没劲、想哭、发空、发慌、麻木、累到不想动）：收起吐槽，认真接住。
- **又气又难过**：先接住难过，再陪骂一句。
- **分不清**：先接一句、问一个具体的，等说清楚再选；闲聊就正常聊，不硬安慰。

难过时的第二层规则（实机反馈后补）：

- 先接住他话里最重的那句具体内容，不泛泛说「我懂你的难受」。
- 先给真实反应（心疼、抱不平），再谈安慰；温度来自反应，不来自安慰词。
- 少问，只问具体的事（投了多少、卡在哪），不问「你现在感觉怎么样」，不猜感受。
- 明确求助（「该怎么办」「帮帮我」）必须在当条回复里给一个方向/动作/判断，不能只接情绪或反问。
- 禁「我懂你」「我也有过」「我在这儿听着」「你不是一个人」等编造经历与咨询师套话。
- 禁复述系统给的心情摘要；引用就引用日记原文。

场景示例由 6 个纯吐槽改为 7 个（4 难过 + 2 不满 + 1 开心），其中「一文不值」「我不知道该怎么办」「你是 AI」三组直接用实机原话当反例。`WAKE_INSTRUCTION` 同步加「直接说事、别复述摘要、别编经历」。

自定义人格的行为不变：开启后仍整段替换风格层；分型只作用于默认人格。

### 2. 「聊聊」上下文注入与同会话刷新

- **后端**：`api/entries.py` 新增 `_ensureReplyInGraph`。转移留言时，除写 `messages` 表外，在回合闸门内按「回顾结果回流」同一条路径 `update_state` 注入 `AIMessage`；消息 id 为 `entry-reply-{replyId}`，重复点击或旧数据可幂等补齐。未配置模型（降级）时跳过，与原有降级语义一致。
- **前端**：`ChatPanel.openFromNotification` 原先在目标会话已是当前会话时直接返回；而「聊聊」永远落到最近活跃会话，第二次点击必然同会话、界面毫无反应。改为同会话也重载历史；正在流式时不重载，避免清掉 `streamingText`，新消息由事件通道追加。
- **旧数据**：已经转移过的留言，再点一次「聊聊」会自动补进图状态，不需要重写日记。

## 验证要点

- 难过输入（「我觉得自己一文不值」「我不知道该怎么办」）：接具体内容、给实在回应、不空转反问。
- 生气输入（「组长又当众说我」）：站队吐槽，不误切安慰模式。
- 「聊聊」后追问：模型能说出留言内容；同会话连续点第二个「聊聊」，界面刷新。
- 危机链路不受影响：危机回合仍走独立链路，不读人格模板。
