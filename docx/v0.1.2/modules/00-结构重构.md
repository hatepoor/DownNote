# 00-结构重构

## 元信息

- **所属版本**：v0.1.2
- **对应代码**：`src/down_note/agent/tools.py`、`src/down_note/agent/prompts.py`、`src/down_note/core/prompts.py`、`src/down_note/db/models.py`、`frontend/src/style.css`、`frontend/src/api/client.ts`、`frontend/src/components/`、`frontend/src/main.ts`
- **前置依赖**：无（最先执行，01~09 均依赖本模块）
- **状态**：已完成（2026-10-08）

## 背景

现有前后端共 7 处混装文件：`tools.py`（4 个领域的工具挤一个文件）、`agent/prompts.py`（5 个角色提示词）、`core/prompts.py`（3 种提示词）、`db/models.py`（6 个实体 + 30 余个访问函数）、`style.css`（1596 行全站样式）、`api/client.ts`（5 个领域接口 + 类型 + 基座）、`components/`（17 个组件平铺）。耦合高、改动落点不清。目标是项目原子化、低耦合：同一类型放同一软件包，软件包下每个文件只放属于该文件的内容。

## 方案要点

- **纯搬家不改行为**，但"路径不变"要分两层说清：
  - **后端**：各包 `__init__.py` 汇总导出，外部（`api/`、`core/`、`scheduler.py`、`tests/`）import 路径不变，`tests/` 零改动即可全绿。
  - **前端**：`components/`、`api/`、`styles/` 目录会迁移，消费方 import 路径**随之机械更新**。现状 `vite.config.ts` 未配 `resolve.alias`，代码一律相对路径——**本次不新增 `@/` 别名**，保持相对路径风格。
- 后端拆 4 处：`agent/tools.py` → `agent/tools/`（clock/diary/memory/session 四域，一工具一文件）；`agent/prompts.py` → `agent/prompts/`（一角色一文件）；`core/prompts.py` → `core/prompts/`；`db/models.py` → `db/models/`（一实体一文件）。
- 前端拆 3 处：`style.css` → `styles/`（按现有分节注释切纯 CSS 文件，不进组件 scoped）；`api/client.ts` → `api/`（一域一文件）；`components/` 平铺 → shell/diary/chat/memory 四个域子包。
- **样式入口衔接**：`main.ts` 的 `import './style.css'` 改为 `import './styles/index.css'`（入口仍是单点，路径随迁移更新）。
- `Entry`↔`Mood` 互相引用改字符串延迟解析（SQLAlchemy 标准做法），消除拆分后的循环导入。
- 顺手清理死代码 `_nowIso`（`tools.py` 内定义但从未被调用）。
- 四决策（2026-10-07）：样式只切纯 CSS 文件；`views/ChatView.vue` 保留；CrisisMark→diary、HotlineCard→chat、ModelConfigDialog→shell；`memory/list.py` 保留此名。
