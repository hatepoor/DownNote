## 踩坑记录

1. **联调写接口不要打在真实数据目录上**（2026-10-08 发现）：真实库 `settings` 表里的 `base_url` / `model_name` / `temperature` 曾被写成测试值（`http://model.local/v1`、`test-model`、温度 1），与 `tests/test_api.py` 的 CORS 用例载荷逐字一致。用户的真实模型配置被覆盖、应用不可用。已从 `down_note.db.bak-20261007-103010` 恢复（写前另存 `down_note.db.bak-20261008-115113`、`…-150122`）。**今后凡写接口联调，先 `DOWN_NOTE_DATA_DIR=<临时目录>` 或用测试库，禁止直连真实数据目录**。
2. **根因已定位（2026-10-08 晚些补正）：是测试，不是"有人 PUT"**。`test_corsPreflightForTauriShell` 当时**没有请求任何夹具**，却执行 `PUT /api/settings/model`（载荷正是那组测试值）→ `config.getDatabaseFile()` 落到真实数据目录 → 静默覆盖用户配置。**为什么之前误判为"测试干净"**：我用主库文件的 hash/修改时间来判，而库是 **WAL 模式**，写入先进 `-wal`、主库文件要等检查点才变——所以看起来"没动"。**教训：判断 sqlite 是否被写，必须连 `-wal`/`-shm` 一起校验，或直接比对内容**。
3. **已加固**：`tests/conftest.py` 新增 `autouse` 的 `isolateDataDir`——**每个用例**都把 `DOWN_NOTE_DATA_DIR` 指向 `tmp_path`，忘请求夹具也不可能写真实库；同时该用例补上 `dbFile`（它需要建表）。修复后整轮 88 passed，且跑前跑后**全部 db 文件 checksum 一致**（含 WAL）。

- 2026-10-08 开发态窗口改为**无边框 + 应用自绘标题栏**：`create_window(frameless=True, easy_drag=True)`，标题栏改为两种壳都渲染（新增响应式 `isShell`——pywebview 桥晚于挂载注入，一次性判断会漏），三个窗口按钮经 `UiBridge.windowAction` 接 `minimize/maximize/restore/destroy`。**根因**：原生标题栏（带系统图标、底色与页面有色差）造成"系统窗口套应用"的割裂观感；安装版本来就无此问题。
- 2026-10-08 紧接上一个踩坑：`easy_drag` 的默认行为是**页面任意位置都能拖窗**，把分隔栏拖拽彻底抢掉（拖左/右分栏变成拖整个窗口）。修法：`webview.settings["DRAG_REGION_DIRECT_TARGET_ONLY"] = True`，只有带 `.pywebview-drag-region` 的元素能拖窗；标题栏（`header` / `.t-brand` / `.t-name`）同时挂该 class 与 Tauri 的 `data-tauri-drag-region`，两条壳语义一致。
- 2026-10-08 第三个开发态窗口踩坑：最大化后点按钮无法还原。**根因**：pywebview 的 `Window.maximized` 属性只是构造参数、`maximize()` 不会更新它，于是"toggle"永远走最大化分支。修法：`windowAction('toggleMaximize')` 里用 Win32 `IsZoomed(hwnd)` 判断当前状态（`restore()` 本身能正常还原，实测代码路径确认）。
