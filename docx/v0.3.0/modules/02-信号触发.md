## 背景

v0.2.0 主动陪伴按档位频率随机开口；「触发信号」（连续低落与强度突变）是当时明确遗留的术语伏笔。本版把它落地：检测到信号时不再等频率轮到，而是本轮巡检即开口，且开口内容针对近几天的状态——从「按频率开口」进化到「它察觉到你了」。

## 方案要点

### 检测器（纯程序，挂进巡检环）

每轮巡检（5 分钟一次）在既有判定**之前**增加一个信号检查项；信号开口与普通开口共用同一开口执行路径（生成、落库、通知、让路、退避全复用）。

### 表一：信号判据（保守触发）

| 信号 | 判据 |
|---|---|
| 连续低落 | 连续 2 个自然日：当日有低落标签日记 且 日均强度 ≥5 |
| 强度突变 | 单日日均强度 比 前 3 日均值 突升 ≥4 |

- 判据基于心情记录（Mood 表）按自然日聚合，纯程序判定、无模型调用。
- 「低落标签」以心情分析产出的标签体系为准（低落族：低落/难过/失落/沮丧/空虚/麻木，`core/prompts/analyzeMood.py` 的 `LOW_LABELS`）。
- 取数窗口「近几天」定 7 天（`WINDOW_DAYS`，总纲待定项就此落定）；取数基准为传入的 `now`（不用系统时间，保证测试可复现）。
- **从宽说明（有意为之）**：「前 3 日」取最近 3 个**有记录**的日子，不强求是连续自然日——低频写日记的用户也能被覆盖。

### 表二：信号状态

| 项 | 规则 |
|---|---|
| 已处理标记 | 检出且实际开口后，该信号标记已处理（落库口径：开口成功才算处理，跳过不算） |
| 冷却 | 开口后 48 小时冷却，同一波低落不反复触发；冷却期内检测继续跑但不开口。**两类信号（连续低落 / 强度突变）各自独立冷却**（`signal_handled_at:low` / `signal_handled_at:spike`）——低落开口不压制突变 |
| 重置 | 连续低落序列中断（某日无低落标签日记或日均强度 <5）即重置计数 |

### 表三：开口时机与礼貌规则（完全同规则）

| 项 | 规则 |
|---|---|
| 时机 | 检出未处理信号 → 本轮巡检即发起开口，不等 `nextAt` |
| 时间窗 | 09:00–22:30 内才开口；越窗 → 信号保持未处理，次日窗口内巡检再次命中 |
| 当日上限 | 计入档位当日上限（信号开口不是额外次数） |
| 让路 | 正在写日记/正在对话中/**刚启动（启动缓冲）** → 让路，信号保持未处理，下轮巡检再试。信号**只豁免「未到点」（频率等待），不豁免启动缓冲**——刚启动不开口 |
| 未回退避 | 与普通开口同一退避计数（连续 3 次未回当日停止） |
| 优先级 | 信号开口与频率开口同轮都命中时，信号优先（内容更有针对性）；开口后 `nextAt` 照常重算 |

### 开口内容（针对性）

- 复用主动开口的生成链路（同人格、同工具边界、空回复兜底），**不新建生成任务类型**。
- 上下文装配扩展：`agent/context.py` 在既有「最近日记 + 心情 + 长期记忆 + 当前时间」基础上，信号开口时叠加「近几天心情轨迹 + 信号描述」（如「用户已连续两天低落，日均强度 6.5」）。
- 提示词层面（`agent/prompts/companion.py`）组织成「对你这几天状态的关注」，不开诊断腔、不下判断，像朋友察觉到「你这两天好像不太对劲」。

### 归属与降级

- 无独立开关：主动陪伴开启时信号检测才跑；关闭时巡检与现状完全一致。
- 信号检测本身不依赖模型；开口生成在降级下按主动开口规则跳过（不补发不攒），信号保持未处理——模型恢复后下一轮巡检仍可命中。
