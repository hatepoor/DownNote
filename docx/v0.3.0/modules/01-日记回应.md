## 背景

写日记从「记给硬盘」变成「说给它听」。心情分析已经产出情绪标签、强度与摘要，回应生成直接复用这份产出，不产生第二次分析调用。回应是它对这一篇日记的留言——不是主动开口，所以不弹通知、不进会话。

## 方案要点

### 数据层

- 新表 `entry_replies`：`id`、`entryId`（唯一约束，一 entry 一回应）、`replyText`、`sessionId`（可空，「聊聊」转移后记录目标会话）、`sessionMessageId`（可空，转移后记录会话内消息 id）、`createdAt`。
- 回应是条目的附属物，与会话体系解耦；删除会话不动它（见总纲「会话删除」决策）。
- 术语命名遵守项目 camelCase Python 风格与既有表命名。

### 生成链路（挂分析管线尾）

```text
条目落库 → 心情分析（现有，成功产出标签/强度/摘要）
        → 回应生成（新增，异步不阻塞）
           输入 = 条目原文 + 心情分析结果 + 人格（不带长期记忆）
           输出 = 一两句（低落认真接住 / 平静简短打招呼 / 开心跟着开心）
        → 落 entry_replies，前端条目下方显示
```

- 提示词新增 `core/prompts/entryReply.py`（常量名 `ENTRY_REPLY_PROMPT`），风格参照 analyzeMood.py；按情绪调节的分档措辞写进提示词本体。
- 分析失败 → 无回应；用户点「刷新」触发重跑分析，成功后管线重走到回应，**无需专门补跑机制**。
- 回应生成失败（模型调用失败）→ 静默跳过，不重试、不补（与主动开口「不补发不攒」一致）。
- 每条日记只回应一次（entryId 唯一约束兜底，重复生成被拒）。

### 「聊聊」转移

- 回应卡片尾部「聊聊 →」按钮：点击后**零模型调用**——回应原文作为 Agent 消息追加到最近活跃会话（无会话则新建），前端跳会话页。
- 转移后记录 `sessionId` / `sessionMessageId`，重复点击只跳转不重复落库。
- 会话被删除：条目上的回应文本保留，「聊聊」按钮回到可点状态（`sessionMessageId` 指向的消息已不存在）。

### 开关与降级

- 独立开关（设置 → 陪伴页新增「日记回应」项），**默认开启**；存 settings 表，键名随 02 设置页实现定（如 `diaryReplyEnabled`）。
- 关闭时：新日记不生成回应（已生成的回应保留显示——开关管生不管删）。
- 降级模式（未配置模型/调用失败）：静默跳过不补。
