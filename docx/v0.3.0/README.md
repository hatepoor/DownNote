# v0.3.0 · 陪伴感深化

> 状态：进行中（2026-10-13；00 已完成，01/02 代码已全部落盘——新增 26 例测试、全量 149 例绿、前端构建通过，待用户实机验证；03 打包发布本轮不执行；04 已落盘待实机复验）。

## 需求来源

用户口述（2026-10-13，brainstorming 收敛，原始口径见本节）：

1. 版本基调：**陪伴感深化**——从「按频率开口」进化到「它真的有在认真读你的日记、真的在乎你的状态」。
2. 功能范围（多选确认）：**日记回应 + 信号触发**。主动跟进、周期回顾、语音日记、数据导出、回顾可视化、密钥加密存储等方向本轮不做。
3. 日记回应：有情绪就回应（不分情绪正负）；回应附在条目上（非落最近活跃会话）；点「聊聊」跳会话页继续聊；回应独立开关、默认开启。
4. 信号触发：提前开口时机 + 开口内容针对性（基于近几天心情轨迹）；保守触发门槛；完全遵守普通主动开口的礼貌规则；随主动陪伴开关生效，无独立开关。
5. 架构（方案一）：日记回应挂分析管线尾部（异步、不重复分析），信号检测进主动陪伴巡检环（复用让路/退避/窗口/上限）。
6. 降级处置：日记回应静默跳过不补（与主动开口「不补发不攒」一致）。

## 版本目标

写日记从「记给硬盘」变成「说给它听」：每篇日记下方都有它的一两句留言；连续低落时它不再等频率轮到，而是带着对你这几天状态的了解主动开口。

**设计总尺子**：回应是「对这一篇的留言」，信号是「对这几天的关注」——两者都是它单方面的关心，不弹通知、不进会话（聊聊除外）、不追着用户跑。

## 范围

**做**：00-术语与文档同步、01-日记回应、02-信号触发、03-打包发布、04-记忆工具按日期定位修复（用户 2026-10-13 报 bug：`listMemories` 未暴露创建日期，Agent 无法按「某天记的那条」定位记忆；日记不可删是铁规矩，历史管理走记忆域）。

**不做**：主动跟进（结构化话题采集与调度，独立成版）；周期回顾（周度对话总结）；回应的批量管理界面；信号可视化标记（留给回顾可视化版本）；回填历史条目回应（从新日记开始）；回顾可视化与密钥加密存储（顺延至后续版本）；「清空全部会话」。

## 关键决策（已定 2026-10-13）

| 决策项 | 定论 |
|---|---|
| 回应落点 | 附在条目上（`entry_replies` 表，entry_id 唯一）；不进会话、不弹通知——它是对这篇日记的留言，不是主动开口；点「聊聊」后回应原文作为 Agent 消息追加进最近活跃会话（零模型调用），`session_message_id` 记录已转移，重复点击只跳转不重复落库 |
| 回应条件 | 有情绪就回应：低落认真接住、平静简短打招呼、开心跟着开心——不在开心时沉默，避免「只在难过时才搭理你」 |
| 回应生成 | 心情分析成功后异步追加一步；输入 = 条目原文 + 心情分析结果 + 人格，**不带长期记忆**（第一版从轻）；输出一两句，像朋友在朋友圈评论；每条日记只回应一次（entry_id 唯一） |
| 回应开关 | 独立开关，默认开启（写日记是用户主动行为，回应是基础体验）；设置 → 陪伴页 |
| 信号判据（保守） | 连续低落：连续 2 个自然日「当日有低落标签日记且日均强度 ≥5」；强度突变：单日日均强度比前 3 日均值突升 ≥4 |
| 信号状态 | 检出并开口后标记已处理；**48 小时冷却**（同一波低落不反复触发）；连续低落中断即重置 |
| 信号开口 | 本轮巡检即开口（不等档位频率）；**完全同规则**：时间窗 09:00–22:30、计入档位当日上限、让路、未回退避全部遵守 |
| 信号内容 | 复用主动开口生成链路（同人格、同工具边界），上下文从「最近日记」扩展为「近几天心情轨迹 + 信号描述」，提示词组织成「对你这几天状态的关注」 |
| 信号开关 | 无独立开关，主动陪伴开启时生效（它修饰的是主动开口的时机与内容） |
| 回应与信号 | 不特殊处理同日并发：条目回应是「对这篇的留言」，信号开口是「对这几天的关注」，上下文天然不重叠 |
| 降级模式 | 回应静默跳过不补（分析失败 → 无回应；点「刷新」分析成功后管线重跑、回应自然补上，无需专门补跑机制）；信号检测为纯程序判定，不依赖模型可用性，但开口本身在降级下按主动开口规则跳过 |
| 会话删除 | 不动 `entry_replies`（回应挂在条目上）；已转移的回应消息随会话一起删，条目上的回应文本保留，「聊聊」按钮回到可点状态 |
| 旧版升级 | 历史条目无回应不回填；新术语与新开关对存量数据无迁移需求 |

已定（2026-10-13 计划评审收口）：

- 信号检测取数窗口「近几天」**定 7 天**（`signals.WINDOW_DAYS`）；取数基准为传入的 `now`
- 信号判据从宽：「前 3 日」取最近 3 个有记录的日子，不强求连续自然日
- 信号开口**只豁免「未到点」（频率等待），不豁免启动缓冲**——刚启动不开口，与模块 02 表三「刚启动」让路一致；`_skipReason` 为此新增 `ignoreNextAt` 参数（与开发自测口子的 `ignoreTiming` 并存）
- 两类信号（连续低落 low / 强度突变 spike）**各自独立冷却**（`signal_handled_at:low` / `signal_handled_at:spike`）

待定（需用户拍板，代码审查提出）：

- **陈旧低落反复触发**：「连续低落」只取最近两个**有记录**的日子，不要求这段低落延续到现在——10-08/10-09 低落过、之后停笔，到了 10-13 仍会命中，冷却 48 小时后 10-15 又命中一次，如此循环。模块 02 表二的「某日无低落标签日记即重置」与表三「对这几天的关注」都指向「延续到现在」，但「近几天」的具体判定口径（要求最近一条记录落在 `now` 当天 / 前一天 / 两天内）未定，**实施时未擅自收紧**
