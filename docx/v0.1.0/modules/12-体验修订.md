## 背景

用户验收测试（2026-10-06 第二轮）提出五项：① 日期显示相对词（"昨天"）不清晰，要具体年月日与星期；② 模型输出 Markdown，前端需要渲染；③ 设置里要能改思考强度与温度（带注释、真实生效，默认 低 / 1.1）；④ 在记忆页点"历史"仍停留在记忆页，导航应以最后一次点击为准；⑤ 模型时间认知有误（问"昨天的日记"找到今天的），需要一个查询日记的工具。

## 方案要点

1. **日期格式**：一律 `2026/10/5 周一`（历史抽屉天列表、日页标题）；日页内条目只显示 `HH:MM`；注入给模型的日记日期改为完整 `2026-10-05 21:08`，整合日记标注「整合日记」——消歧义，配合 ⑤。
2. **Markdown 渲染**：新增依赖 `marked` + `dompurify`（打包进 bundle，无网络资源）；`utils/markdown.ts` 统一 renderMarkdown（breaks + gfm + 消毒）；ChatBubble 的 assistant 气泡渲染富文本（用户气泡保持纯文本）；流式光标改为 CSS 挂在 `.md-body.streaming` 的最后一个子元素后。提示词同步放开：陪伴基调允许少量 Markdown，危机应答不再禁止加粗。
3. **模型参数设置**：配置弹窗新增「温度」（0–2，默认 1.1）与「思考强度」（关闭/低/中/高，默认低），均带界面注释；settings 表存 `temperature` / `reasoning_effort`；`ModelServiceConfig` 增字段；`buildChatModel` 真实应用（关闭 = 不传 reasoning_effort；温度在两条路径都传）；PUT 校验（0–2、枚举）；「未设置」与「空串（关闭）」区分处理（`or` 会把空串误吞，需显式判 None）。
4. **导航点击优先**：点「历史」若在记忆页 → 先切回工作台再开抽屉；抽屉点某天 → 无论当前视图直接切工作台并打开那天的日页；点「记忆」顺带收起抽屉。
5. **日记查询工具**：新增主智能体工具 `queryDiaries(date, keyword)`（纯代码读库）——按日期返回那天整合日记 + 原文（没有则明说）；按关键词搜索（含整合日记）；工具说明要求先把"昨天"用 getCurrentTime 换算成日期。models.py 增 `searchEntries`；陪伴提示词指引使用该工具。
