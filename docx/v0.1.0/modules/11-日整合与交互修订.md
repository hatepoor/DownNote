## 背景

用户验收测试（2026-10-06）提出四项修订：① 记忆不即时生效（会话系统提示是唤醒时的快照）；② 历史条目点击不跳转；③ 日记/对话分栏不可拖拽调整；④ 当日内容跨天后应自动整合成一篇日记，并由模型分析沉淀长期记忆（重复不添加 / 冲突修改 / 不存在新增）。

## 方案要点

1. **记忆即时生效（①）**：对话每回合开始前对比「长期记忆 + 最近日记 + 日期」快照，有变化才重建系统提示并原位替换线程里的 SystemMessage（删旧追加新）；稳态零改动，保住追加式与前缀缓存。应用重启后每个会话首次回合刷新一次。
2. **一天一篇日记（④）**：`entries` 加 `kind` 列（`entry` 当天条目 / `daily` 日整合日记），`SCHEMA_VERSION` 2→3 用 `PRAGMA user_version` 迁移补列（旧数据回填 `entry`）。跨天后纯程序把当天条目按时间升序以 `\n\n` 拼接成一篇日记，幂等（已有整合日记的日子跳过）。
3. **整合后的链路**：兜底扫描分析出"日心情"（复用 `analyzeEntry` 与危机初筛）→ 记忆管理子智能体按「重复→不动 / 冲突→改 / 新增→记」沉淀长期记忆（`DIARY_MEMORY_PROMPT`，与对话维护共用同一套工具和规则），成功后写 `daily_memory_done:<日期>` 标记，失败不标记、下轮重试。
4. **触发时机**：兜底调度每 30 分钟依次执行：日整合 → 未分析补扫 → 日记记忆沉淀；应用没开则下次启动补齐（存量历史一并整合）。
5. **按天浏览（②）**：历史抽屉改为天列表（`GET /api/diaries`：日期、条数、预览、当天心情），点某天 → 左栏切到那天的日记页（`GET /api/diaries/{day}`：整合日记 + 当天原文，只读，带"回到今天"）。
6. **拖拽分栏（③）**：工作台两面板之间加拖拽柄（6px，含 hover 朱砂线），宽度范围 [320, 窗口宽-464]，localStorage 记忆（`down-note:diary-width`），双击复位 472。
