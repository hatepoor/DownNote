## 背景

本版主题：开启后 Agent 像朋友一样自己开口。产品用于写负面情绪，陪伴要给足——频率给够，靠"随机时机 + 让路 + 未回退避"保证自然，不靠"少说话"来避免打扰。

## 方案要点

- **开关与档位**：读 `settings`（默认关闭）。关闭时与现状完全一致（用户唤醒后才回应），不加任何前置门槛。
- **程序判定，模型只说内容**：巡检（纯程序）决定"此刻该不该开口"，命中后才发起**一次生成任务**——复用现有主智能体链路（同人格、同工具边界）；"一次"指不为"是否开口"额外问模型，实际可能包含工具调用与空回复兜底的多次模型请求。
- **会话定位**：落点 = **最近活跃会话**（术语表定义：`last_active_at` 最新）。生成开始取候选，落库前校验会话仍存在；与用户回合共用同一会话锁（`turnLock`），用户回合优先，锁被占用则本次放弃、等下一周期。
- **不抢焦点**：主动开口只落库与通知，**不自动弹窗**打开窗口；窗口不在前台才发系统通知（01）。
- **降级**：未配置模型或调用失败 → 本次跳过，不补发、不攒。

### 表一：计时与计数

| 项 | 规则 |
|---|---|
| 巡检周期 | 每 5 分钟一次（纯程序，无模型调用；到点即开口，误差 ≤5 分钟） |
| 下一次开口时刻 `nextAt` | 每次成功开口后：`nextAt = 开口时刻 + 档位间隔区间内的随机值`（冷淡 4~6h / 正常 2~3h / 关心 1~2h），不是固定钟点 |
| 当日上限 | 冷淡 3 / 正常 6 / 关心 12；按自然日（本地时区）重置 |
| 窗口约束 | 只在 09:00–22:30 内开口；`nextAt` 晚于 22:30 → 顺延到次日 09:00 起 60 分钟内的随机时刻 |
| 最小间隔兜底 | 任何情况下两次开口相隔 ≥45 分钟（覆盖切档、重启等边界） |
| 启动 / 重启 / 休眠恢复 | 不逐条补发错过的开口；启动缓冲（10 分钟）结束后，若 `nextAt` 已过且在窗口内，允许开口一次 |
| 切换档位 | 立即按新档位重算 `nextAt`（锚点仍是最近一次开口），仍受最小间隔与窗口约束 |
| 跳过一次机会 | 让路 / 降级 / 锁占用 → 本次跳过，`nextAt` 不变，下次巡检验；不累积、不补发 |

### 表二：让路判据（活动状态一律按"最近 N 分钟有动作"判定，自动过期）

| 条件 | 判据 | 过期 |
|---|---|---|
| 正在写日记 | 日记编辑界面有未提交草稿，或 5 分钟内有编辑 / 保存动作 | 5 分钟无新动作即失效 |
| 正在对话中 | 会话页 5 分钟内有用户消息 / Agent 回复 / 未发送的输入 | 同上 |
| 刚启动 | 本次进程启动后 10 分钟内 | 10 分钟后失效 |
| 窗口收进托盘 | 视为不活跃 | — |

### 表三：在途开口的处置（生成完成时按序判断）

| 情形 | 处置 |
|---|---|
| 开关已被关闭 | 丢弃，不落库 |
| 目标会话已被删除 | 丢弃，不改投、不新建 |
| 用户此刻处于活跃（表二）或已越过 22:30 | 落库，不弹通知（会话开着可直接看到） |
| 其余 | 落库；窗口不在前台 → 发系统通知（通知绑定该会话，见 01） |

### 表四：未回退避

| 项 | 规则 |
|---|---|
| 什么算"回了" | 主动开口之后，用户在**任一会话**里发消息（打开通知但未发言不算） |
| 不连发 | 一次开口后不追加第二条；下一个周期照常开口（新话题，不算追） |
| 退避阈值 | 连续 3 次开口均未被回 → 当日停止开口；次日恢复 |
| 解除条件 | 用户随时发消息 → 未回计数清零、恢复正常节奏；若发生在别的会话，落点也随之切到该会话（活跃时间已刷新）；会话被删除 → 计数清零，落点重新开始 |
