## 背景

用户实测：对话历史只能看不能删——后端有 `GET /history`、`GET /sessions` 可读，没有任何删除路由，前端历史抽屉也只有列表没有删除入口。

## 方案要点

- **入口**：对话页的历史抽屉，每条会话一个删除；**删除前二次确认**，文案写明"删除后不可恢复"。
- **删除范围**：只删这次对话本身——`messages` → `sessions` → LangGraph checkpoint（`thread_id = session_id`）三处物理清；**长期记忆一律不动**，不做任何连带；也不做"清空全部会话"。
- **删除期间的不变量（硬性）**：删除成功后，任何在途任务不得再写入或恢复该会话——回复或主动开口的生成任务在**落库前校验会话仍存在**，不存在则丢弃（不改投、不新建，见 05 表三）。
- **执行与失败处理**：删除接口幂等（重复调用无副作用）；顺序为先清 checkpoint（幂等可重试），再在同一事务里删 `messages` 与 `sessions`；中途失败则前端报"删除失败，可重试"，重试安全，不出现半删状态。
- **界面状态**：删掉当前打开的会话后，前端切到最近活跃会话；一条都没有则回到空态（可唤醒）。
- 删除后前端列表即时刷新（沿用现有 SSE 推送，或本地移除兜底）。
- **边界说明**：删除会话只保证这次对话消失；不承诺模型此后不再提及相关事实——那些事实可能仍存在于长期记忆或日记里，需要用户各自删除。
