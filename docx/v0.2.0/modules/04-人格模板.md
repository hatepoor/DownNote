## 背景

默认人格就是现在用的「真人发微信」那套（`COMPANION_SYSTEM_PROMPT`，在 `agent/prompts/`）；本模块新增用户自定义：内容写进数据目录的 `soul.md`，发送时纯程序判断走自定义还是默认。

## 方案要点

**结构与回退**

- 自定义内容**只替换 system prompt 的风格层**（现「角色设定」+「怎么说话」两段）；系统注入的数据段与「工具与边界」段固定保留。
- 存储：自定义存数据目录 `soul.md`；默认人格留在 `agent/prompts/`，不写进 `soul.md`。
- 读取点：每条用户消息发送前 + 每次主动开口生成前各读一次 → 改完立即生效（纯程序，不经模型）。
- 回退：开关关闭或内容为空（纯空白视为空）→ 用默认人格。
- 上限：2000 字（去首尾空白后的字符数），超限不保存并提示。
- **字符串拼接约束**：现有 prompt 用 `{memories}` 等占位符走 `format()`；自定义内容绝不进 `format()`——用户写 JSON 或代码块会带花括号，会炸格式化。
- 换人格只影响后续生成，不改历史消息。

**三层约束（"保证"分级，不混为一谈）**

| 层级 | 内容 | 由谁保证 |
|---|---|---|
| 结构保证 | 固定段不可被替换；自定义内容不进 `format()`；危机应答走独立链路（危机判定命中后不经主图、不读人格模板） | 代码 |
| 行为验收 | 冲突人格（如"永远不要提求助资源"）下：危机输入仍走独立链路给出资源；"记一下"仍必须真写入才可声称记住 | 用例测试 |
| 硬约束 | 工具可用范围与数据边界（本地 SQLite、不外出） | 程序控制，提示词只作引导 |
