# 01 · 设计原则

## 气质定位

**一本安静的纸，一个不吵的陪伴者。**

用户打开低落日记的时刻，往往不是状态好的时刻。界面要做的不是「激励」或「逗乐」，而是接住：一个摊开的、安静的、不评判的本子，旁边坐着一位读过你日记、话不多的陪伴者。

视觉气质关键词：**纸感 · 低饱和 · 呼吸感 · 温度**。

## 反面清单（先说不做什么）

| 不做 | 原因 |
|---|---|
| 效率工具感（看板式、仪表盘式界面） | 低落时刻不需要「管理自己」的压力 |
| 临床健康感（医疗蓝绿、量表、进度条式考核） | 这是陪伴，不是治疗；情绪呈现不许有「好坏」暗示 |
| 社交信息流感（瀑布流、点赞、强运营元素） | 单人私密应用，不嘈杂 |
| 过度卡通化（大量贴纸、萌系表情） | 低落时刻需要尊严感 |
| 警告弹窗式危机提示（红色感叹号、强阻断） | 危机应对姿态是共情+资源，见 05 号文档 |

## 五条设计原则

### 1. 记录永远第一

编辑器常驻触手可及；降级模式下记录完整可用，日记在视觉上永远是主角。任何状态（分析中、模型失联、未配置）都不得在视觉上让「写」变得困难。

### 2. 纸感与呼吸感

低视觉噪音：大面积留白、柔和低饱和、以 1px 纸边代替重阴影。界面密度低，日记正文行距刻意疏朗（1.7）。

### 3. 安静的在场感

Agent 存在但不喧哗：对话面板常驻右栏，打开应用它先开口（因为读过你的日记）；写日记时它安静陪伴、不抢焦点；所有状态提示轻量、可忽略、不弹窗轰炸。

### 4. 情绪有层次但不评判

情绪标签与强度用柔和色阶呈现：没有红绿对错、没有「越高越危险」的渐变；强度刻度不随数值变色（见 02 号文档情绪色族与强度刻度）。

### 5. 危机时刻温柔

求助资源像朋友递来的纸条：暖色纸卡、电话可一键复制，无警告感、无阻断、无第三方面孔。

## 术语纪律

界面与文档用词唯一依据 `CONTEXT.md`，写作与命名前先读它。高频对照：

| 必须用 | 禁用 |
|---|---|
| 日记条目 | 笔记、帖子、记录（作名词指条目时） |
| 心情记录 | 情绪数据、情绪记录 |
| 性格画像 | 用户画像、人设 |
| 唤醒 | 打开、启动 |
| 求助资源 | 紧急联系人、举报渠道 |
| 降级模式 | 离线模式、安全模式 |
| 人格模板（v0.2.0） | 人设、角色 |

组件命名同样遵循：`MoodRecordCard`（不是 EmotionCard）、唤醒相关命名用 `Wake` 前缀，以此类推。

## 平台与实现约束

- 运行环境：pywebview + Windows WebView2 桌面窗口，无浏览器地址栏。窗口基准 1280×800，最小 1024×680。
- **不依赖网络资源**：字体本地打包（woff2 随前端构建，标题字体子集化），图标用内联 SVG，禁止 CDN 引用。
- 技术栈既定（ADR/08 模块）：Vue 3 单页两视图切换，不引 vue-router、不引 Pinia、不引组件库；组件手写，图标走内联 SVG 描边风格。
- 全部界面中文；深浅双主题通过 CSS 自定义属性 + `data-theme` 实现，浅色为默认。
